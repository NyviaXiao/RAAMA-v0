# RAAMA 工业级金融 RAG 与 Harness 自进化重构建议

日期：2026-10-24。状态：设计建议，尚未实施。本建议扩展上一轮已验收的本地 Harness 工程范围，不把拟新增能力写成现有能力。

## 1. 产品目标与验收原则

目标是构建面向金融投资研究的 Agent 系统：能够在指定信息时点，从复杂金融文档和结构化数据中取得可核验的证据，完成研究、反证和组合分析，并通过独立评估持续改进研究策略。

核心亮点有两项：

1. 工业级金融 RAG：复杂文档与表格理解、多路检索、精排、可追溯引用、金融时点与口径控制，以及能够定位问题的质量评估。
2. 工业级 Harness 自进化：持久执行、有限恢复、策略版本、失败归因、可解释的离线策略优化、独立验收、影子验证和完整回滚。

“工业级”由可运行的能力、测量结果和故障演练证明。安装向量数据库、增加 Agent 数量或使用 GEPA 本身不构成验收。

成本不作为当前选型约束；延迟、吞吐、资源上限、调用次数仍需测量和控制，以保证稳定性、交互体验与实验可比性。

默认沿用当前 A 股研究场景，同时把证券标识、交易日历、会计口径和执行规则设计为可扩展接口。

## 2. 必须解决的核心痛点

| 痛点 | 设计方案 | 必须提供的验收证据 |
|---|---|---|
| PDF 可以读出文字，但数字串列、单位丢失、跨页表错拼 | 结构化文档模型、版面/OCR/表格解析、跨页表重建、数字校验与低置信度隔离 | 原页面到单元格的定位；关键数字、单位、列头、跨页连接的人工标注集与失败案例 |
| 找到语义相似段落，却找不到回答所需证据 | 精确财务查询、BM25、稠密向量、文档树、视觉页面等检索路由；融合后重排 | 按问题类型拆分的 Recall@K、nDCG、完整证据集合召回率和消融实验 |
| 历史回放混入后来修订和未来资料 | 不可变来源、知识时间与业务有效时间、时点过滤、版本化索引和特征 | 插入未来文档、更正公告和回填数据后，旧快照结果保持不变 |
| 引用真实，但不能支持结论 | 原子主张与证据绑定、数值计算工具、冲突检测、未知与拒答 | 逐主张支持标注、财务口径检查、无答案和相互矛盾资料测试 |
| Agent 运行长、中断后重做、请求未知时重复扣费 | 持久步骤、幂等调用、未知结果对账、检查点和恢复协议 | 杀 worker、数据库/模型超时、重复消息、半完成发布等故障演练 |
| 提示词改了，却不知道哪里更好 | 模块化实验矩阵、冻结数据、失败归因、GEPA 受限候选、独立留出验收 | 可重放候选包、固定基准、全部尝试登记、配对结果与置信区间 |
| RAG 指标漂亮，但没有研究或投资价值 | 文档/检索、研究任务、经济效果分别验收 | 有无 RAG、固定查询/自适应查询、不同渠道的同条件比较 |

## 3. 目标架构与职责

### 3.1 数据与证据服务

数据源接入 -> 原始对象与来源登记 -> 文档解析 -> 财务事实与文档树 -> 分层块 -> 多种索引 -> 不可变语料发布版本。

原始文件、页面图像、解析结果、表格、块和 Embedding 都是版本化派生工件。所有派生结果必须能追溯到原文件哈希与解析版本。

### 3.2 在线研究与决策

用户任务 -> 任务与权限预检 -> 固定数据/模型/策略版本 -> 经理规划 -> 证据查询/专家研究/反证质询 -> 证据与主张校验 -> 历史成熟反馈校准和数值融合 -> 组合优化 -> 硬风控与咨询性风险研究 -> 投资经理反馈 -> 决策及影子执行工件。

RAG 以类型化工具服务提供能力，不作为每个专家各自维护的知识库。市场、基本面、新闻、情绪/关注度和风险专家共享相同证据权限、版本和来源定位协议。

账户状态用于本地判断信息重要性和组合约束，不改变事实可信度，不默认进入公共检索词、外部 Embedding 或模型请求。

### 3.3 评价与演化控制

执行轨迹 -> 故障与质量分类 -> 开发集实验 -> 候选生成 -> 选择比较 -> 独立验收 -> 前向影子 -> 发布或拒绝 -> 持续监测与回滚。

生产策略运行期间固定。修改提示、检索配置或模型不会直接修改生产指针。

## 4. 建议技术选型

| 职责 | 建议主选 | 使用方式与边界 |
|---|---|---|
| 权威元数据、权限、任务、版本和评价登记 | PostgreSQL | 作为事实与状态的权威记录；SQLite 保留本地轻量模式 |
| 原文、页面图、解析、模型和实验工件 | S3 兼容对象存储 | 内容哈希、不可变版本、保留策略、备份恢复；关系库保存引用 |
| 关键词与字段检索 | OpenSearch | BM25、金融词典、证券标识、字段检索和结果浏览 |
| 稠密向量与多向量检索 | Qdrant | 按语料版本、模型版本和维度隔离；过滤与向量查询共同执行 |
| 文档解析 | Docling 统一结构适配层 | 不依赖某解析器专有结果作为业务契约 |
| 中文复杂 PDF、扫描件挑战解析器 | MinerU、PaddleOCR/PP-Structure | 通过金融文档标注集选主用/降级路径，避免每份文档无条件跑所有解析器 |
| Embedding 候选 | Qwen3-Embedding、BGE 系列 | 用真实中文金融检索集选型；模型大小和通用榜单不等于业务最好 |
| 重排候选 | Qwen3-Reranker、BGE reranker | 绑定任务指令、版本、输入上限和分数校准 |
| 持久流程 | Temporal | 文档导入、重索引、研究任务、评估和发布流程；外部副作用置于 Activity |
| 观测与实验展示 | OpenTelemetry + Langfuse | 接入本地审计与脱敏遥测；发布权威记录留在业务状态库 |
| RAG 评价与回归 | 自建标注/确定性评分 + Ragas + promptfoo | 自动裁判仅作辅助，金融数字和关键主张必须可人工复核 |
| 自进化 | 既有 Harness + GEPA | 保留已验证的硬规则，通过受限策略包扩展演化空间 |
| 工作台 | 类型化 API + React/Next.js 等前端 | 文档来源定位、检索轨迹、实验比较、任务恢复与发布审计 |

OpenSearch 与 Qdrant 都有混合检索能力；这里采用两索引是为了明确区分文本分析/结果浏览和向量/多向量服务。引入两套索引后，必须同时实现版本发布和一致性校验。若基准证明单一后端足以覆盖需求，可保留同一接口并收敛部署，不把组件数量当亮点。

当前已验证的事实校验、成熟标签校准、数值优化、风险检查、交易账本、独立发布门禁及历史路径应保留契约与回归测试，通过适配层迁移。

## 5. 多格式解析与统一文档模型

### 5.1 输入格式与解析路由

- 数字 PDF：先读取文字层与页面几何结构，检测乱码、阅读顺序异常和表格缺失，按需升级 OCR/视觉解析。
- 扫描 PDF、PNG/JPEG：方向/倾斜校正 -> 版面识别 -> OCR -> 表格/公式/图表识别。
- DOCX、HTML、Markdown、TXT：优先保留原生标题、列表、表格、链接和段落层级。
- XLSX、CSV、XBRL/JSON：保留工作表、单元格、维度、事实字段与来源；精确数值问题优先结构化查询。
- PPTX：保留页、图表、文字和布局关联，不将幻灯片文本简单拼接。

格式支持以逐格式真实样本、错误分类和可恢复任务验收，不能以扩展名列表证明。

### 5.2 统一结构

Document -> Section -> Block -> Paragraph/Table/Figure -> Cell/Span。

每层记录：文档与版本 ID、原文件哈希、证券/实体、标题路径、页码、坐标、字符区间、解析器与模型版本、置信度、原始值与规范值、来源地址和时间。

金融字段至少保留：指标、数值、币种、单位、倍率、报告期、期初/期末、当期/累计、母公司/合并、原披露/重述，以及支持该口径的表头和附注。

“—”、空白、0、负数括号、百分比和基点不能随意互换；单季度值与累计值转换必须经过可审计计算。

### 5.3 质量闸门

低置信度、解析器严重分歧、关键单元格缺失或口径不明的内容，进入待核验区。不得悄悄变成确定事实进入收益或风控数值。

表内合计、资产负债关系等一致性检查用于发现错误，不能保证原始文件或解析结果必然正确，也不能强行改数字使其平衡。

## 6. 跨页表格、层级切块和原文展开

跨页表重建必须发生在普通切块之前。检查表名/续表标记、列头与列数、列位置、币种单位、证券主体、报告期、行的延续关系；去掉重复表头时保留其来源。

确认延续的表产生统一 table_id 与连续行/单元格 ID，同时保留每一页的坐标。无法确认时保留分表和“可能延续”关系，不强行拼接。

提供三类可关联视图：

1. 小块：用于检索定位，可从约 200–500 token 范围起步实验。
2. 父级章节/表格/行组：用于解释和口径核查，长度按任务和预算配置。
3. 原页/原文：用于页面定位和人工验证。

长表按行组切分，并重复必要的多级列头、单位、期间与脚注引用；不能在单元格中间按字符硬切。

块模型包含 parent_id、previous/next、table_id、row_range、page/bbox 和标题路径。Agent 命中子块后，可以受控展开父章节、相邻段落、相关附注与原页面；摘要不替代原始事实。

Docling 的结构模型与层级切块、LlamaIndex 的父子块/自动合并、PageIndex 的目录树导航适合作为参考。目录摘要属于派生索引，不能独立充当财务事实证据。

## 7. BM25、Embedding、多路召回与重排

### 7.1 “并行 BM25 关键词索引”是什么意思

BM25 是关键词相关性排序。倒排索引可以把“经营活动现金流”等词映射到包含它的文档块，综合词频、词的稀有程度和文档长度进行打分。

它不是简单统计出现次数，也不依赖 Embedding。中文金融检索需要正确分词、财务词典、证券代码/简称/历史名称保护和字段设计。

“并行”表示对同一个合法查询，同时执行关键词检索和语义向量检索，再合并结果：

- “600519 2024年报 合同负债”侧重代码、年份与术语精确匹配。
- “预收款增加是否反映需求改善”需要语义表达匹配。

BM25 分数、向量相似度和重排分数不是相同尺度，更不是事实正确概率；不能直接相加并设一个通用阈值。

### 7.2 统一查询计划

QueryPlan 显式记录任务类型、实体、别名、报告期、信息截止时点、口径、需要回答的子问题、允许来源、检索路由和证据覆盖条件。

证券、时点、权限等约束受代码保护。模型可以提议同义改写、分解问题和补充查询，不能悄悄改变这些约束。多轮对话每次继承已确认的约束；含糊实体应明确消歧。

### 7.3 六类检索通道

| 通道 | 适用问题 | 返回对象 |
|---|---|---|
| 结构化事实/只读查询 | 财务字段、期间比较、精确数字 | 带原始单元格和口径的事实 |
| BM25/字段检索 | 证券代码、专业术语、公告标题 | 文本块与字段命中 |
| 稠密向量 | 同义表达、事件含义、自然语言问题 | 语义候选块 |
| 目录树/章节导航 | 年报长文、多章节与附注核查 | 章节、页和父级证据 |
| 页面视觉/多向量 | 图表、复杂版面、OCR 损失场景 | 页面/区域及文本关联 |
| 关系检索 | 产业链、关联交易、同主体跨文档关系 | 带时点和来源的关系边 |

六路不必每次全部启动。基础数值问题优先查结构化事实，解释类问题走关键词与语义，复杂长报告再展开目录和视觉，关系问题按需加入关系检索。

### 7.4 宽召回与精排

建议起始实验配置：多路各召回若干十条，合并为约 100–200 个去重候选 -> RRF 融合 -> 独立 reranker -> 选取约 10–20 个证据块 -> 按需展开父级与附注 -> 覆盖检查。所有数量是初始实验参数，不是性能结论。

RRF 根据不同列表中的名次融合，避免直接混加不兼容的分数。reranker 接收问题与候选内容，细查问题相关性；它不能保证事实正确、来源可信或答案完整。

去重必须识别同一公告的转载、同一供应商的重复记录和同一事实的重复块，防止大量副本挤掉反证或被当成独立支持。

### 7.5 动态检索与阈值

是否继续查询由证据覆盖、数值/期间/口径是否齐全、冲突是否未解和新增信息量共同决定。允许扩召回、改写、读父级、查询反证、换来源或明确停止/拒答。

阈值按任务类型和锁定模型，用开发集校准，在独立集验收。不能把 cosine>0.7 或任意 rerank 分数当作通用正确标准。

### 7.6 分页

用户浏览采用稳定排序与游标，必要时结合搜索引擎快照；研究任务固定已检索候选与证据集，避免每翻一页就改变答案依据。

OpenSearch 的数据库 PIT（Point in Time 搜索快照）用于稳定搜索视图，和金融信息的 as_of 可见时点是两个不同概念。快照一致性不能替代金融时点过滤。

## 8. 金融时点、权限与多索引一致性

至少区分事件/业务有效时间、公布时间、首次可用时间、实际捕获时间、系统入库时间、修订时间。原版与更正版并存；检索根据研究任务的知识时点选择可见版本。

公告今天补抓到，即使披露日期在去年，也不能冒充系统去年已经捕获。严格前向来源与回顾性代理需分开状态。

索引元数据包括证券/实体、版本、来源权限、所有时间、报告期、币种单位、解析与 Embedding 版本、块/父级 ID、原文哈希和语料发布 ID。

权限与金融时点必须在检索服务端执行，不能等候选正文已经被送给模型后才过滤。

历史评估还要固定 BM25 语料统计、索引快照、摘要、图谱和模型/特征训练版本；只给未来文档加过滤条件不等于所有未来影响都已消除。预训练模型可能拥有后来知识，必须限制结论的证据依据，并将真实前向验证单独保留。

PostgreSQL 为权威来源。使用事务 outbox 分发解析/索引任务；消费者按内容哈希与版本幂等。只有所有必需索引和工件校验通过，才发布同一个 CorpusRelease。查询包固定其 manifest 与物理索引版本；不能分别切换两个后端导致半新半旧。

模型或向量维度变化创建新索引，离线重建、验证、影子比较后切换，保留回滚视图。来源撤销/权限变更必须使检索和缓存及时失效；历史重放也不能绕过现行访问权限。

## 9. 生成、精确计算与逐主张引用

生成器输出四类内容：来源事实、确定性计算、推断解释、未知/争议。每个重要主张绑定 supporting/refuting evidence、版本、页/单元格位置和适用口径。

精确财务计算走类型化只读工具、Decimal 或确定性计算器。模型提出计算计划，代码验证指标、单位、期间和操作；不直接信任模型心算，也不把任意生成代码或 SQL 直接运行。

引用检查分层：来源存在 -> 实体和时点正确 -> 数字/单位/期间对应 -> 主张是否被证据支持 -> 是否漏掉关键反证。自动语义裁判只能辅助，关键投资主张需要抽样人工复核。

页面视觉检索可辅助定位，但图表估读数值应明确标注；无法可靠提取时，不作为精确财务事实使用。

## 10. 召回/生成 × 解析/Query/匹配优化矩阵

该矩阵组织实验与故障归因，不要求部署六套独立服务。

| 阶段 | 解析模块 | Query 模块 | 匹配模块 |
|---|---|---|---|
| 召回阶段 | ①版面/OCR路由；②跨页表重建；③语义与行组切块；④层级/页/单元格关联 | ⑤实体与别名消歧；⑥时点/期间/口径抽取；⑦受约束查询改写；⑧多跳问题分解 | ⑨BM25；⑩Embedding与多路召回；⑪RRF/来源去重；⑫独立rerank |
| 生成阶段 | ⑬父级/附注展开；⑭财务事实与表格规范呈现；⑮保真压缩和上下文预算 | ⑯答案计划与证据覆盖；⑰补查/质询/拒答与停止 | ⑱逐主张引用对齐；⑲确定性计算核对；⑳矛盾、口径和无依据主张验证 |

先逐模块消融，再比较少量组合；解析变化后重建索引并重测召回，检索改善后再评估生成。不能同时改解析、Embedding、重排、生成提示和评估器，再把收益归给单一技术。

## 11. 工业级 Harness 的重构要求

### 11.1 可恢复执行

任务状态包含目标、约束、已知/未知、计划、已执行动作、引用证据、剩余预算、待对账请求和下一步。保存结构化决策理由与工具轨迹，不依赖隐藏思维过程恢复。

外部调用按至少一次执行可能性设计，采用唯一操作 ID、结果对账和幂等写入。未知投递不能盲重发；对支付、交易等有副作用工具设置独立边界。

Temporal 管理跨服务持久过程；数据库保存业务状态和工件。模型、网络与解析调用放在 Activity，不放入要求确定性重放的 Workflow 逻辑。框架恢复不等于业务副作用恰好执行一次。

### 11.2 记忆和 Context Reset

- 不可变事实记忆：来源、版本、定位、哈希与时间，不让摘要覆盖原件。
- 任务记忆：状态、未知、步骤、证据集合和未决调用，可跨进程恢复。
- 程序经验：失败模式、修复、适用条件、失效条件与评价证据，可停用和回滚。
- 表现/校准记录：成熟标签、损失、覆盖、市场状态与窗口，保持任务和证券身份。

Reset 前落盘 checkpoint；恢复时核对数据、索引、提示、工具、模型、策略与权限版本。压缩只替换上下文呈现，不修改权威事实。

### 11.3 三个学习/决策对象分开

1. 研究策略：何时查询、调用哪个专家、是否质询、如何组装和何时停止。
2. 数值校准与专家融合：用已成熟标签训练，独立报告预测误差和分状态表现。
3. 资产权重：由数值优化器结合用户约束、实际账户和风险计算。

模型写一段更积极的研究结论，不能直接提高某专家的数值权重或资产仓位。

## 12. 自进化的候选空间与发布控制

### 12.1 可学习范围

在 schema 内演化角色提示、查询分解、同义扩展、检索路由、候选数量、融合权重、重排任务指令、父级展开、上下文分配、补查/质询/停止规则和程序经验。

当前六文本候选需要升级为有界策略配置与组件版本引用；硬代码解释配置，不执行候选携带的任意代码。

解析器、Embedding、reranker、切块等变更属于独立离线流水线实验，通过重建和评价产生候选包。生产中不随调用自行换模型或修改索引。

### 12.2 不可学习范围

权限、as_of、原始事实、风险限制、评价标签/分区/规则、发布权限、账本和幂等语义不得由候选修改。代码级架构改动通过正常评审发布，不进入无人审核的生产自修改。

GEPA 可以从失败轨迹和文本反馈优化候选，但不会自动提供安全边界、正确评价器、持久执行或发布治理。

### 12.3 优化目标

先过权限、时点、财务数字和执行安全门禁，再比较证据覆盖、主张支持、任务完成、拒答适当性和稳定性；延迟、资源和调用负担作为约束或 Pareto 维度保留。

不能只优化“回答问题时的正确率”：它会鼓励大量拒答。必须同时报告回答覆盖率、错误回答率、无答案识别和任务类型分层结果。

投资层独立比较相同账户、预测、风险和执行条件下的净效用。不要让单次历史收益成为所有模块共用的奖励；这无法区分研究质量、行情偶然性与回测过拟合。

### 12.4 完整版本包

包含代码与依赖、工具 schema、提示与策略、解析器、块策略、Embedding/reranker 与指令、语料/索引 manifest、特征与校准模型、训练来源、评价器和数据分区、风险与执行规则。

开发 -> 选择 -> 独立验收 -> 前向影子 -> 发布/拒绝。已查看验收反馈再调参即登记为污染；登记失败与所有尝试，不只保存最好的一次。

## 13. 量化评价体系

| 层级 | 测量内容 | 防止的误判 |
|---|---|---|
| 解析 | OCR字符错误、表格结构、单元格数值/单位/期间、跨页链接、页坐标、低置信度覆盖 | 文本读出来不代表财务表读对 |
| 召回 | Recall@K、完整证据集合召回、MRR、nDCG、反证覆盖、来源重复率、过滤拒绝率 | 命中一页不等于取得全部证据 |
| 重排与上下文 | nDCG增益、重要证据保留、每千token有效证据、压缩保真 | 相似度高不等于信息充分 |
| 生成 | 数值与口径正确率、逐主张支持、引用定位、无依据主张、拒答和覆盖曲线 | 自动裁判高分不等于答案可靠 |
| Agent | 完成率、补查价值、质询纠错、重复动作、停止质量、中断恢复、幂等 | 调用更多工具不等于研究更好 |
| 系统 | P50/P95/P99、吞吐、索引延迟、可用性、恢复时间、数据丢失窗口、跨索引一致性 | 单机smoke不等于生产稳定 |
| 投资 | 净效用、风险、回撤、费用、成交约束、换手、分市场状态和信息增量 | QA改善不等于收益改善 |

FinQA、TAT-QA/TAT-DQA、FinanceBench 的公开部分可作为外部诊断集。不能把它们的公开题当作唯一独立验收：语言/市场不一定匹配，也可能存在模型训练污染。

自建中文金融集至少覆盖：直接事实、跨页表、附注口径、多年比较、重述、公告/新闻冲突、图表、长文多跳、无答案、时间边界、源权限和恶意文档。标注不只给答案，也给必要证据集合、财务口径、允许计算和应拒答原因。

按公司、文档家族、报告期和事件防止近重复跨分区；投资反馈按时间顺序、标签成熟和 embargo 切分，不能随机拆股票行。

建议先建设数百个经过专家核验的高质量种子任务，扩展到千级并持续保留新公司/新报告期盲测；明确样本量和置信区间。合成题用于扩充回归，不能取代真实独立人工标注。

### 建议发布门槛（待基线与样本量确认，不是现有结果）

- 权限、禁止时点、生产门禁绕过测试不允许出现通过路径；保留实际负面测试工件。
- 关键数值问题的必要证据 Recall@50 先以 >=95% 作为候选目标，同时报告全证据集合覆盖。
- 数值、单位和报告期正确率与回答覆盖率联合验收；关键错误不得被总体平均值掩盖。
- 每个重要结论必须有可打开的原文定位；支持关系单独抽样标注和评审。
- 新版本需相对冻结基准有可复现改善且无关键类别退化；保留配对置信区间和多次尝试记录。
- 明确交互式查询与深度研究两类 SLO，按目标数据规模和真实并发压测设值；生产候选提供备份恢复、容量和故障演练报告。
- 投资改善必须独立验收；没有未来成熟数据时保持 pending，不用合成收益替代。

## 14. 工程运行、安全与工作台

模块化实现，按解析CPU/GPU、Embedding、重排、检索、Agent和评价等资源/故障边界拆 worker。可使用容器与调度平台，但不能以部署 Kubernetes 代替可恢复实现。

版本化 OpenAPI/JSON Schema；请求取消、超时、背压、幂等键、有限重试、死信与人工修复；支持任务暂停、恢复和明确终止。

缓存键包含权限、知识时点、语料/索引、模型、策略与工具版本。对话记忆、事实缓存、Embedding和执行结果缓存分开，不让旧权限或旧语料的结果被跨任务复用。

文档导入处隔离解析进程、禁宏、限制资源和文件类型。来源文本作为数据；恶意 PDF/网页不得提升工具权限、修改硬规则、发消息或执行任意代码。公共知识、私有文档和账户数据分区，出站/日志脱敏，保留受控审计明细。

贯穿 ingestion_id、document/version/chunk/table_id、corpus_release、query_id、task/run/trace/span、strategy/package_id。一次失败应能定位在解析、Query理解、召回、重排、压缩、生成、校验或执行，而不是只看到“LLM回答错误”。

工作台应提供：

- 原 PDF/页面与引用片段、表格单元格并排展示，点击结论可打开来源。
- 同题查看各检索通道、融合名次、重排结果、过滤与去重原因。
- 经理计划、专家意见、反证、质询、未知和停止理由。
- 组合权重、风险检查、执行限制、费用与账本核对。
- 中断/恢复、未决调用对账、版本差异、实验比较和发布审计。

## 16. LightRAG 与关系层的具体位置

实体关系有明确金融用途：母子公司、供应链、担保、关联交易、人物任职、同一事件跨公告传播。

先定义带时间、来源和实体消歧的关系 schema，再比较关系检索与文档多跳检索。如果证据证明关系路由改善完整取证、且新增错误可控，可将 LightRAG 等适配器放入对应通道。

关系抽取和社区摘要是派生推断，不能自动变成权威事实。过时关系必须能失效；未来文档不得通过图索引或摘要进入过去的任务。

## 17. 实施顺序、交付和退出条件

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| A 问题与基准 | 投资研究任务、标注协议、数据权利、基线与保留契约 | 能明确判断哪些问题要查文档、需要什么证据、怎样算错 |
| B 证据数据模型 | PostgreSQL/对象存储、来源时间/版本、解析和财务事实schema | 原文到单元格可追溯；修订/回填/未知正确区分 |
| C 多格式与表格 | 解析路由、OCR/布局、跨页表、层级块和页面定位 | 按文件类型和困难样本完成解析评价，不静默丢失关键事实 |
| D 检索与重排 | BM25/Embedding、结构化/目录/视觉通道、融合、rerank、版本化索引 | 固定标注集上有召回/排序/完整证据的独立结果与消融 |
| E 研究Agent与工作台 | 类型化工具、主张引用、计算核查、补查质询、可读来源界面 | 真实端到端任务和无答案/冲突任务可验收 |
| F Harness与演化 | 持久流程、Reset、受限策略包、GEPA失败反馈、独立发布 | 故障恢复不重复副作用；候选改善可归因、可回滚 |
| G 投资验证与运行 | 预测/投资分账、同账户配对、真实影子、并发/恢复演练 | 工程、研究和经济状态分别通过；不足证据明确pending |

所有阶段都产出实现、契约、测试、样本、测量结果与运行说明。禁止用静态页面、编造指标或只有合成演示的证据宣称工业级。

优先保留当前已验证契约与数值链路，用特性开关、影子读、新旧适配器和版本化索引迁移；不以重构为理由破坏历史重放或删除已有工程证据。

最终交付应是能演示并重放“来源变化 -> 解析/索引 -> 研究 -> 校验 -> 决策 -> 评价 -> 候选改善 -> 独立验收”的系统，同时能展示一次解析失败、一次证据不足拒答、一次中断恢复、一次候选拒绝和一次完整回滚。
