# PostgreSQL adapter contract and feasible coverage matrix — 2026-10-27

## Scope and status

`PostgresIndustrialRagStore` subclasses `IndustrialRagStore`. PostgreSQL-specific code is limited to connection handling, row construction, migrations, transaction setup, and a small SQLite-SQL translation layer. Most repository methods are inherited and need the same observable contract as SQLite while executing through psycopg. The object store is injected separately; this matrix tracks the combined store/object behavior only where the service workflow needs both.

Several bounded PostgreSQL 17.11 runs already pass against synthetic records, including rollback, outbox concurrency and lease fencing, continuation review, query-cache upsert, release publication, application retrieval, and restart/reconnect. They do not constitute the full adapter suite. `backend_status()` deliberately continues to report `postgres_contract_suite_verified: false`. PostgreSQL HA, failover, restore, and multi-node behavior have not been tested or implemented by the current Compose probe.

## Completion rule

Do not change `postgres_contract_suite_verified` to true until one reusable contract suite runs against both `IndustrialRagStore` and `PostgresIndustrialRagStore`, checks every applicable method above, compares normalized results and failure semantics, and passes its rollback/concurrency/restart cases. Keep HA as a separate claim requiring a multi-node failure and recovery design plus evidence. This matrix is a map of verified slices and remaining tests; it is not an acceptance certificate.
