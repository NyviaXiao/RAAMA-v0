# RAAMA 多智能体 Harness 自进化系统最终实施方案

日期：2026-10-24。审阅基线：772b4fd20a4cc27342434eb16aec6515c2cad419。

本文固化父审核聊天与用户讨论形成的最终方案。用户已授权实施全部阶段，由新建 GPT-6 Luna、xhigh 编码聊天完成代码，父聊天独立审核、复核测试并处理环境阻塞。方案是目标契约，不能将未实现项目写成既成事实。

## 1. 定位与原则

构建“按需多智能体研究 + 历史校准与专家融合 + 数值组合优化 + 独立风险与经济验收”的真实工程系统。

自进化解决：给定证据、专家表现、市场与账户条件，获取什么信息、调用谁、是否质询、如何交接、何时停止、哪些受约束策略值得采用。优化器解决：给定校准收益、不确定性、账户与用户约束，计算目标持仓、现金与成本。

- 保留市场、基本面、新闻、情绪/关注度四类能力，按需调用，不要求每案四个模型全部运行。
- 保留研究经理、风险审查、投资经理的职责。简单计算使用确定性工具，不能只改角色名称冒充独立 Agent。
- GEPA 离线进化研究策略；生产任务固定版本，执行中不自我更新。
- 数据权限、时点、事实校验、预算和硬性风控由代码执行，不允许候选修改。
- 研究采用与生产发布分开；研究质量和投资效果分别报告。
- 数值融合权重、证据可信度与资产持仓权重是三种不同对象。
- 不引入无实际需要的复杂集群、消息平台或图数据库。

## 2. 现状与迁移

现有 GEPA 主线是行情/基本面/研究经理三角色，六文本组件演化；具备评分、账本、缓存、版本、程序经验与回滚。当前公共缓存回顾性 PIT 未严格验证，历史候选拒绝，不能声称投资改善。

contextual_rl.py 保留成熟反馈选择预定义融合方案的历史入口，其查询动作禁用，状态键主要使用市场状态。agentic_rl.py 另外有 Expected SARSA 的 study:finish/study:query 与融合研究路径。二者不得混淆，也不得与 GEPA 拼接描述为已接通的统一流程。历史入口与产物保留可重放，当前生产仅使用一个发布策略。

已知审阅问题：通用压缩白名单会丢失 facts 动态指标键、symbol 与 vintage 信息；_validate_report 接受错误数值/报告期，离线评分不能代替运行门禁；基本面搜索按股票代码截取有偏置；adopt 在冻结评估前写共享 active 指针；共享 JSONL 不具备并发事务预算；模型解析/工具失败缺统一有限修正；旧 public_expert_overlay 两项测试与独立组件契约漂移。审阅时 164 passed/2 failed；请重新核对而非盲改测试。

## 3. 统一运行链路

任务/账户预检 -> 固定数据/模型/策略/预算版本 -> 本地状态 -> 经理规划与信息循环 -> 多专家按需调用/原文/反证/质询 -> 事实证据校验 -> 候选与已验证研究特征 -> 校准融合 -> 数值优化 -> 独立硬风控与可选风险研究 -> 投资经理说明 -> 决策工件/影子执行 -> 预测与账户分别结算 -> 离线评价与进化。

每步保存工件、输入/输出哈希、状态、时间和错误；只传结构化交接，原文通过 evidence_id 按需读取。经理候选必须真实影响候选范围；风险意见必须进入最终反馈，硬拒绝不能被叙述覆盖。

## 4. 角色和动作

- 市场：趋势、反转、量价、波动和流动性；指标不冒充收益率。
- 基本面：财务字段、报告期、公告，公司变化；区分报告期、披露、可用、抓取和修订。
- 新闻：事件、可信度、去重、影响渠道、支持与反证；标题不冒充正文。
- 情绪/关注度：有真实文本时才报告文本情绪，有指数时只能报告该来源关注度；缺失明确 unavailable，不伪造。
- 研究经理：计划、下一动作、指定主张质询、候选排序、停止。
- 风险：始终执行现金/风险/集中度/换手/容量/交易规则硬检查；按需做事件/行业/模型风险研究。
- 投资经理：根据方案、已验证证据、风险结论及执行限制生成反馈，不随意修改数值权重，不绕过风险拒绝。

允许动作：市场证据、财务/公告、新闻、情绪/关注度、原文、指定专家反证核查、风险研究、停止。质询有目标主张/来源/待解决问题；记录支持/推翻/未知与后续变化。每案预算、深度、次数硬限制；相同无新增信息动作应能识别并停止。

分歧只是线索；检查来源独立性、覆盖、不确定性及对组合的重要性。查询/不查询/固定查询/策略查询要能配对比较；资料不足不能推断渠道无价值。

## 5. 状态与融合

本地状态包括成熟专家损失/校准误差/样本量/覆盖稳定性；方向和证据分歧、来源重叠；收益/波动/流动性市场状态；现金/持仓/风险/集中度/容量账户状态；已查来源、未知、预算与研究状态。

账户主要决定信息重要性和组合约束，不能改变事实可信度。公共专家默认不接收账户金额、持仓明细或私有逐证券预测；派生状态出站有明确白名单与审查。

首先保留成熟误差+等权收缩基线，然后实现可独立评估的低维正则状态条件融合。文本必须先形成可复现特征，用已成熟训练标签校准后才能进入收益数值，否则仅做候选/风险证据。学习专家融合与查询策略时分开实验，不让多个控制器同时改变以致无法归因。账户效用驱动融合是独立比较项。

## 6. GEPA 与提示工程

可演化：角色策略、经理信息获取/质询/停止、上下文选择和交接、程序经验、固定解释器支持的有限路由配置。不可演化：安全/时点/权限、工具实现、事实校验器、评价器与数据分区、风险限制、优化器、生产指针。配置只能使用允许的动作/条件/有界参数，不执行任意候选代码。

循环：冻结基准和开发协议 -> 执行留痕 -> 失败归因 -> GEPA 提案 -> 开发/选择比较 -> 研究候选 -> 独立验收 -> 影子运行 -> 发布/拒绝。GEPA 不会自动创造未提供的工具，运行时使用固定候选策略，不进行逐调用参数训练。若引入 RL，单独对照再组合。

四层提示：固定政策（来源文本作为数据等）；可演化角色策略；动态任务/证据/经验上下文；代码强制工具契约。版本绑定代码、提示、模型、工具schema、校准模型、评价器、配置、数据清单与依赖；保存差异、采用/拒绝依据。

## 7. 上下文、记忆、召回和 Reset

按工具类型压缩并保持 symbol、field、value、unit、report_period、published_at、available_at、fetched_at、vintage、来源定位、冲突/未知及 reopen 引用。摘要不能覆盖原始事实。压缩需有字段保持/重新读取回归测试。

任务状态持久化计划/步骤/未知/预算/下一步；不可变事实存储原始来源/时间/版本/哈希；程序经验记录失败模式/修复/适用与失效条件，经评价采用，可停用/回滚。不得把某股票临时结论当长期程序经验。

召回：权限/时点 -> 股票/事件/报告期 -> 相关性 -> 去重与来源独立性 -> 支持/反证 -> 预算组装。记录丢弃原因和压缩事件，区分事实/推断/争议/未知。长任务 reset 保存工件和状态后重新核对版本、来源、预算、未决请求；短任务先修压缩与恢复。

LightRAG 不是基础依赖。先完成结构化与文档检索，提供跨文档关系任务对照和可接入边界；只有独立证明增益才启用。图索引、实体合并、摘要也必须遵守 as_of。

## 8. 校验与恢复

分层验证输入/参数、来源存在与可见、股票/指标/数值/单位/报告期、主张证据支持、进入候选/数值链路资格、组合及执行约束。结构化数字由来源规范读取优先。缺证据 unresolved，不静默补值。

模型格式错在预算内有限修正；缺证据限制用途；已确认临时失败有上限退避；投递未知先对账，不自动重发；中断从持久阶段恢复预算；优化不可行明确原因；硬风险失败阻断。降级明确记录，hold 也检查可行性。事务预算预留、幂等任务/反馈/执行与恢复不重复扣费。

## 9. 优化与真实金融执行

保留近端梯度：同期限同单位的校准收益 - 不确定性 - 风险惩罚 - 调整成本；多头、现金含费、单票、风险、换手、容量、候选与不可交易持仓约束。与成熟求解器对照目标差距、收敛与可行性；自写 constrain 不当成精确联合投影，不以可行冒充全局最优。

落地历史成分/状态、修订与首次可见、公司行动、停牌/涨跌停成交能力、股数/可卖数量/交易单位、费用/滑点/容量、风险暴露/压力情景。适用市场规则须由可信资料核实和配置版本化，不凭记忆一刀切。保留研究名义金额模式并明确差别，提供真实数量账本/执行约束模式与核对。

预测账与投资账分开：成熟预测校准，成交后 NAV 评价投资；未成交非预测错误，延期卖出非原期限标签。真实券商发单、资金操作和公开部署不由本授权自动触发；完成可运行本地应用与影子执行。

## 10. 独立评估与金融结论

三层：工程（契约/时点/压缩/恢复/预算/幂等/硬风控）；研究（事实/引用/主张支持/覆盖/反证/拒答/效率/成本）；经济（净效用、风险/回撤/成本、资金效率、稳定性）。明确 fact_accuracy 是结构化 observations 还是整份主张。

开发/选择/独立验收/前向影子分区；清除跨边界成熟标签泄漏，依赖需要时 embargo；按日期和事件成组而非股票行冒充独立样本。登记所有尝试、已查看区间和版本。test.csv 仅最终隔离评分器可读，研究和开发永不读。验收集反馈后重调即已查看。

历史 LLM 知识污染、回填 vintage 和数据缺口诚实标记；真实前向积累不可用合成数据替代。工程、研究及投资有效性分开状态；外部数据/未来成熟等待不免除完成可实现代码。

对照固定/GEPA；不查/固定查/自适应；等权/误差门控/候选融合；去新闻/去情绪/去质询；固定同账户/预测/优化/执行的数值基线；必要重复配对，不能依赖 temperature=0 假定完全确定。记录实际新增成本和固定可比逻辑成本，费用仅扣一次。

研究采用可因质量/效率改善；生产需预声明独立经济/风险验收，成本下降且效果不劣可作为标准；无证据不宣称收益提升。

## 11. 观测、发布、应用

统一 task/run/trace/span 标识关联检索、调用、校验、优化、风控、决策；可配置接入 OpenTelemetry，并有无需远端的本地可检查输出。观测缺失/陈旧/时点拒绝、事实/来源冲突、费用/延迟/缓存/预算、候选/组合变化、恢复/未知/重复、评价/发布。受控明细与脱敏展示分开。

发布状态 draft -> research_candidate -> acceptance_passed -> shadow -> production。研究不能改 production 指针；独立发布，固定运行版本；回滚完整兼容版本包，记录审计。不要修改已发布的历史结果冒充新实验。

模块化 API + 独立 worker + 持久状态库 + 工件存储 + 工作台。本地 SQLite 起步，实际并发事务/锁和幂等必须能验证；多 worker 需要时再迁移数据库。无需没有需求支撑的 Kafka/K8s/图数据库。

工作台真实接后端：任务提交/进度、来源证据/质询变化、候选/组合/风险、费用、版本差异/验收/回滚。非技术中文 UI，不能用静态 fixture 冒充真实任务和后端。无浏览器测试能力时如实记录并交父介入；不能只 HTTP 200 即声称交互通过。

## 12. 阶段与验收

|阶段|交付|验收|
|---|---|---|
|0 基线|入口/能力/版本/测试契约与方案/需求矩阵|现状可复现，历史路径不误述|
|1 正确性|压缩、事实门禁、召回、错误和测试契约|错值阻断、关键事实保持、失败定位|
|2 统一流程|可选四专家、质询、风险/最终反馈与状态恢复|实际端到端可运行；无数据明确 unavailable|
|3 自适应查询|GEPA 路由/停止进化及固定基线|真实动作执行、独立比较、预算和失败可解释|
|4 校准融合|成熟文本特征与低维状态融合、消融|成熟训练/冻结推理；误差/收益/成本口径一致|
|5 发布|隔离验收、影子、生产指针与完整回滚|候选不能直接生产、私有/未见不泄漏|
|6 金融及应用|数量执行/规则/行动/风险与 API-worker 工作台|账户核对、约束验证、真实 UI/API 流程、限制记录|

全部工程要求需逐条映射代码入口/测试/实际运行证据。真实外部数据、未来成熟期、模型效果不可凭空保证，明确 pending_external/pending_forward/scientific_not_proven，不能用此替代必要实现。若需额外数据或付费调用，先完成可审阅实现与现有允许输入验证，再由父处理必要授权。禁止仅写文档/只造新文件不接主链/以合成 UI 冒充落地。

## 13. 最终交付

架构/数据/接口契约；完整需求追踪矩阵；版本与经验库；可恢复状态与账本；独立评估和验收协议；求解器与金融执行验证；真实本地研究工作台；运行说明和分项限制。每项结论可追溯到工件。项目分别证明机制、研究提升、投资效果，不互相替代。
